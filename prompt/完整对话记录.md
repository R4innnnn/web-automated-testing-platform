### 建议的平台形态

用 **TypeScript + Playwright** 做测试核心，提供一个本地网页界面配置任务、查看进度和报告。用户选择待测目录后，填写或确认**启动命令、就绪地址、入口页面**；仅凭目录无法可靠判断所有 Web 项目该怎样启动。Playwright 支持启动本地服务，并能监听未捕获的页面异常和页面崩溃、保存录像与操作轨迹。[服务启动文档](https://playwright.dev/docs/test-webserver) · [页面事件文档](https://playwright.dev/docs/api/class-page) · [轨迹文档](https://playwright.dev/docs/api/class-tracing)

核心流程可以是：

`选择目录 → 启动软件 → 探索页面与控件 → 捕获异常 → 自动重放 → 汇总 Bug 报告`

探索器先覆盖链接、按钮、表单和返回操作，设置运行时长与动作上限，避免无限循环。报告按错误堆栈和触发页面去重，保存**操作步骤、错误日志、截图、录像、轨迹和重放结果**。网页中的 JavaScript 异常、浏览器页面崩溃、服务进程崩溃应分开呈现；HTTP 404、普通控制台报错等先列为线索，不能直接宣称是已发现的 Bug。

5. 录制从选择目录到查看报告的完整演示，整理使用文档，再发布到 GitHub。

### 技术设计

本地界面用 **Vite + Vue 3 + Element Plus + JavaScript**；后端用 Node.js，扫描任务交给独立工作进程。**Playwright** 负责真实浏览器中的页面探索、登录、截图和录像；请求探测器负责对已发现的参数做受控测试；SQLite 保存任务、页面、测试用例和发现结果，证据文件按任务单独存放。界面显示任务进度、已访问页面与状态转换、发现列表，并允许点开证据和重放步骤。Playwright 提供页面异常与崩溃事件，也能保存操作轨迹。[页面事件](https://playwright.dev/docs/api/class-page) · [操作轨迹](https://playwright.dev/docs/api/class-tracing)

### 六类检测怎样判定

| 模块 | 第一版的验证方式 | 报告为“已确认”的条件 |
| --- | --- | --- |
| SQL 注入 | 对同一参数发送基线与成对探测请求，比较稳定响应 | 排除随机页面变化后，出现可重放的差异证据；单个数据库报错仅作线索 |
| XSS | 对输入点放入唯一标记，在浏览器中观察反射、存储和执行 | 标记脚本实际执行；仅显示原样文本不算 |
| 文件上传 | 用无害标记文件测试类型、内容和访问方式 | 违反该站点明确的上传规则，并能验证后果 |
| 文件覆盖 | 只对平台创建的测试文件尝试同名覆盖 | 原有标记内容确实被替换且可重放 |
| 文件包含 | 对疑似文件路径参数尝试读取预置的无害标记文件 | 返回了本不应暴露的标记内容 |
| 弱口令 | 对指定测试账号做少量、限速的候选验证 | 使用弱密码实际登录成功；失败次数本身不算漏洞 |

这六类并非每个网址都具备可测入口。例如没有上传功能、测试账号或已知的无害文件路径时，对应模块应显示“未满足测试条件”，不能写成“安全”。OWASP 测试指南也将这些项目分别放在输入验证、认证及上传业务逻辑中，需要按具体应用判断。[SQL 注入](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/07-Injection/05-SQL_Injection/) · [XSS](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/07-Injection/01-Reflected_Cross_Site_Scripting/) · [文件上传](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/10-Business_Logic/08-Upload_of_Unexpected_File_Types/) · [文件包含](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/05-Authorization/01-Directory_Traversal_File_Include/) · [弱口令](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/04-Authentication/02-Default_Credentials/)

**崩溃监测单列。**浏览器脚本异常、浏览器页面崩溃和目标网址不可达分别记录。只知道网址时，无法直接观察远端服务进程；连接中断应写“服务不可达”，经过重试仍不能直接断言为服务器崩溃。

### 重点模块的判定方式

| 模块 | 输入、验证和证据 |
| --- | --- |
| SQL 注入 | 发现参数后保留正常请求，做成对条件探测和重复对照；错误信息或一次响应差异仅是线索。源码模式再找输入进入查询的位置。 |
| XSS | 分别测试反射、存储和 DOM 场景；用不窃取数据的唯一标记，确认它在浏览器中执行，保存触发步骤。只回显文本不算。 |
| 文件上传 | 找上传入口，用无害文件验证扩展名、MIME、内容校验和后续访问。上传成功本身不算漏洞，需证明绕过了目标规则或产生安全影响。 |
| 文件包含/路径穿越 | 找文件路径参数；本地靶场用预置标记文件证明越界读取。远程站点没有安全的已知路径时，不读取真实敏感文件。 |
| 信息泄漏 | 检查公开脚本、版本控制及备份入口；证据中只存脱敏片段，不复制令牌或私密源码。 |

**测试账号**是你控制的专用账号，用于登录后爬取、改密测试和有上限的失败登录试验，避免锁住真实用户；测越权通常还需要第二个不同权限的账号。管理员真实账号不做自动猜测。目录模式若能控制目标进程，可用退出码和日志确认崩溃；只输入远程网址时，连接失败只能报告“服务不可达”。
