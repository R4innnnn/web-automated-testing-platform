# Web 自动化测试平台

本机运行的 Web 动态测试平台。用户可以只输入网址，直接探索页面并捕获服务错误、前端异常；也可以输入源码目录，由平台分析 PHP、Python、Java、JavaScript、TypeScript 文件，并连接或启动该项目后做同一套动态测试。SQL 注入等安全模块均为可选项。

## 目录

| 路径 | 用途 |
| --- | --- |
| `readme.md` | 安装、运行和使用说明 |
| `code/backend` | Python API、探索器、检测器、报告生成和测试 |

## 环境与安装

已在 Windows、Python 3.11、Node.js 20.15 上验证。需要 Python、Node/npm 与 Chromium 浏览器下载权限；无需 Docker。PowerShell 在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\code\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\code\scripts\start.ps1
```

浏览器打开 `http://127.0.0.1:8000`。后端只监听本机地址。首次安装脚本会创建 Python 虚拟环境、安装依赖、安装 Playwright Chromium、构建前端。以后只需运行 `start.ps1`。停止平台时在启动终端按 `Ctrl+C`。

## 两种输入

### 1. 网址黑盒

选择“网址 · 黑盒”，填写完整的 HTTP(S) 网址。**不勾选任何安全模块即可点击“开始测试”**，无需授权表单。平台会按广度、深度或随机顺序访问站内链接和 GET 表单，记录页面截图、状态、请求计数、HTTP 5xx、站内 404 和浏览器脚本异常。仅凭远程 HTTP 500 或连接失败无法证明服务进程崩溃。

本机地址和私有网段的安全测试不弹远程授权对话框。非本机公开网址只有在勾选需要主动探测的模块时才会显示风险提示，并要求填写目标范围及授权依据。配置弱项的被动头部和 Cookie 检查不触发主动测试确认；公开网址无授权声明时不会执行其主动 CORS 验证。平台会把跳出范围的主页面导航拦截，探测请求也限定同一站点和路径前缀。平台无法自动证明用户的授权声明真实有效。

### 2. 源码目录

选择“源码目录 · 白盒＋动态”，输入本机目录和就绪网址，再选启动方式：

- **现有服务**：适合已经由 phpStudy、IDE 或其他工具启动的目标。平台只连接服务，不停止原进程。
- **自动识别**：尝试识别 `package.json`、`manage.py`、`app.py`、`main.py`、Spring Boot 或带 `index.php` 的 PHP 项目。
- **手动命令**：输入目标启动命令。平台在源码目录执行该命令，等待就绪网址，再进行动态测试；任务结束后停止自己启动的进程。

源码分析给出“待动态验证或人工核查”的候选位置，**不把命中代码模式直接写成已证实漏洞**。可以填写目标日志路径以捕获本次运行新增的 PHP 致命错误、未捕获异常等；平台自己启动的进程还会记录退出码和标准输出。可选填 `coverage.xml`、LCOV 或 JaCoCo XML，只有提供有效覆盖率报告时才显示行覆盖率。仅提供源码目录不能推导运行覆盖率。

## 安全检测模块

| 模块 | 首版验证方法 |
| --- | --- |
| SQL 注入 | 参数基线、数据库错误特征及受限布尔对照 |
| XSS | 用受控标记在浏览器确认反射、DOM 或可复访的存储型执行 |
| 文件上传 | 上传无害纯文本内容的危险扩展名文件，验证是否公开可取；不上传执行代码 |
| 文件包含／路径遍历 | 只用系统示例文件签名做验证，不保存读取内容 |
| 认证 | 专用账号的弱口令设置、少量易猜凭证、六次有上限的失败登录观察 |
| 信息泄漏 | 少量固定路径的版本库、环境文件与备份文件签名 |
| 配置弱项 | 会话 Cookie 属性、HTTPS 场景及有认证上下文的 CORS 验证 |
| 开放重定向 | 跳转参数的站外目标验证，绝不跟随到外部地址 |

认证模块需要在“登录与专用测试账号”中配置登录页和专用账号；口令策略还需要修改密码页。平台只对用户填写的专用账号尝试密码，不猜测未指定的管理员账号。弱口令策略试验后会尝试恢复原密码，报告会标明是否验证成功。六次失败登录内未观察到限速**不足以证明可无限暴力破解**，因此只写入运行说明，不算作 Bug。没有入口或证据不足的安全类别不进入发现列表。

## 报告与录像

任务完成后，页面展示发现列表、探索时间线、静态候选位置和覆盖率。每个任务会在 `code/backend/data/runs/<任务 ID>/` 生成 `index.html`、每条发现的独立 HTML、`result.json` 与页面截图。运行数据和本机账号不会提交到 Git。密码不写入任务数据库；导出的响应头和敏感查询参数会做脱敏。

[`video/platform-demo.webm`](video/platform-demo.webm) 是本机测试站上的真实操作录像，展示填写目标、勾选 SQL 注入／XSS／开放重定向、任务完成及打开证据报告。标记误报后可在页面恢复，报告会同步更新。

## 本机验证

项目附带**刻意存在漏洞**的最小测试站，只用于检验扫描器。另开终端运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\code\scripts\run_fixture.ps1
```

然后在平台填写 `http://127.0.0.1:8777/`。不选模块可验证基础探索；勾选模块可验证各检测器。该测试站只绑定 `127.0.0.1`，不要部署到公网。

后端集成测试：

```powershell
.\code\backend\.venv\Scripts\python.exe -m pip install -r .\code\backend\requirements-dev.txt
.\code\backend\.venv\Scripts\python.exe -m pytest -q .\code\backend\tests
```

公开练习靶场只作为最后的可用性演示。[Pentest Ground](https://pentest-ground.com/) 的官方页面允许扫描站内靶机，并注明靶机每 30 分钟重置、多人共享。2026-10-09 对其 DVWA 入口进行了**不选安全模块**的黑盒探索：4 个页面、20 次预算内请求、无授权弹窗、无已证实 Bug。正式演示前仍应再次核对其规则、目标范围与可用性。用户已部署的 DVWA 与 sqli-labs 可作为本机测试目标；本次验收时本机 80 端口未提供服务，因此没有把这两个靶场记为已测通过。

## 当前边界

首版的自动探索覆盖站内链接与 GET 表单；需要登录的路径可配置账号。复杂多步骤业务流程需要人工提供入口或后续扩展。静态规则在五种语言中提供候选位置，不能保证发现所有数据流漏洞。目标被现有服务器托管时，若未配置目标日志，只能观察 HTTP 层异常，不能认定目标进程崩溃。命令注入、CSRF、越权、SSRF、XXE、模板注入及不安全反序列化尚未实现。
